# 南得遇見你 管理員操作說明

這份文件是給**完全不懂寫程式**的管理員看的，教你怎麼啟動網站、登入後台、日常怎麼新增/修改/刪除內容。網站正式名稱是「南得遇見你」（程式內部的專案資料夾、部分技術名稱可能還留著舊名「異鄉座標」，純粹是程式內部代號，不影響你在後台看到的畫面跟網站上顯示的名稱）。

> 這份文件會持續更新——只要後續有任何操作方式（新增後台功能、網址變動、指令變動）改變，都會附上最新版本，不用擔心看到舊版說明。

---

## 一、如何啟動網站

**已經有資料的使用者（你目前的情況）：請直接看下一節「二之一」。** 啟動只需要：`npm install` → `npm run db:update` → `npm run dev`，然後開 `http://localhost:3000`。

**不要**對現有資料執行 `prisma migrate dev`、`db:seed` 或 `prisma migrate reset`：它們會建立新資料庫或寫回內建內容、覆蓋後台修改（詳見二之一 E）。全新安裝（沒有任何既有資料）不屬於日常流程，需要時請先向維護者索取專門的初始化步驟。

## 二、如何進入管理員登入頁

網址：**`http://localhost:3000/admin/login`**

> 正式上線後把 `localhost:3000` 換成正式網址即可，以下所有網址都是同樣換法。

登入後，後台導覽完全跟前台網站分開——側邊欄最下面有一個「查看前台網站」，會開新分頁，你的後台分頁本身不會離開，不用擔心誤按跑出後台。

## 二之一、固定資料位置與更新流程（先看這裡）

**核心觀念：程式碼和資料分開放。**
- 程式碼 = 每次收到的新 ZIP 解壓縮出來的資料夾（可以每版一個資料夾、保留各版本）。
- 資料 = 一個固定的資料夾，例如 `C:\Users\<你的使用者名稱>\Desktop\南得遇見你資料\`，裡面有：
  - `dev.db`：網站實際使用的資料庫
  - `uploads\`：所有上傳的圖片
  - `backups\`：資料庫備份
- 新版程式資料夾會自動讀到同一個固定資料夾，所以**換資料夾、換版本，資料都在**。
- 固定資料夾位置記在你電腦使用者家目錄的 `.nande-platform.json`（不在程式資料夾裡，ZIP 不會蓋掉它，也不會被上傳到 GitHub）。
- 設定錯誤時網站與所有工具都會**明確報錯並停止**，不會自動建立新的空白資料庫，也不會悄悄換成別份資料庫。程式資料夾裡就算有另一份 `dev.db` 也完全不會被使用。

### A. 一次性設定（只做一次）
1. 關閉網站（在執行 `npm run dev` 的視窗按 Ctrl+C）。
2. 到**最新版**程式資料夾，執行（路徑換成你的；有空白或中文要用雙引號）：
```
npm install
npm run data:init -- --dir "C:\Users\<你的使用者名稱>\Desktop\南得遇見你資料" --from-db "C:\Users\<你的使用者名稱>\Desktop\<舊版程式資料夾>\prisma\dev.db" --from-uploads "C:\Users\<你的使用者名稱>\Desktop\<舊版程式資料夾>\public\uploads"
```
   它會：建立資料夾 → **複製**（不是搬移）資料庫和既有上傳圖片進去（來源原封不動、同名檔案不覆蓋）→ 記錄位置 → 檢查設定。
3. `npm run db:doctor`：確認連到的是固定資料夾，並看各區塊資料筆數是否和原本一致。這一步也是第一次用 Prisma 實際開啟「中文資料夾」裡的資料庫；如果出現無法開啟資料庫的錯誤，請把錯誤貼給我，臨時解法是改用不含中文的資料夾（例如 `C:\Users\<你的使用者名稱>\Desktop\nande-data`，重新執行 data:init 並加 `--force-config`）。
4. 如果 `.env` 裡有 `DATABASE_URL="file:./dev.db"`，可以整行刪掉（本機模式已不使用它；留著只會看到一則提醒）。`.env` 其他設定（NEXTAUTH_SECRET、管理員帳號等）照舊需要。
5. `npm run dev`，開網站確認資料和圖片都在。
6. 確認無誤後，舊資料夾裡的 `dev.db` 與 `public\uploads` 可以保留當備份（不要再用它們）。你另外做的獨立備份也請繼續保留。

### B. 之後每次收到新 ZIP（完整流程）
1. 把 ZIP 解壓縮到**新的資料夾**（例如 `exchange-student-platform-v2`）。
2. 複製 `.env` 到新資料夾（沒有 ZIP 包含 `.env`；若你已改用環境變數也可省略）。
3. 在新資料夾執行：
```
npm install
npm run db:update
```
   `db:update` 會依序：確認固定資料庫 → 自動備份 → 產生 Prisma Client → 比對資料庫結構 → 健康檢查。
   - 若顯示「沒有 schema 變更需要套用」→ 直接進入下一步。
   - 若顯示「有資料庫結構變更」→ **先看我的更新說明確認風險**，再手動執行 `npm run db:push`（會先自動備份、只新增資料表／欄位、不刪資料）。
4. `npm run dev` 啟動，確認資料和圖片都正常。

### C. 日常指令速查
**更新、補內容（會改資料，都會先備份）**

| 要做的事 | 指令 |
|---|---|
| 資料庫缺資料表／欄位時補上（只新增，不刪除） | `npm run db:push` |
| 把生活區缺的關卡名稱／單字／漫畫補進去（只補缺，不覆蓋） | `npm run db:restore-life -- --apply` |
| 手動備份資料庫 | `npm run db:backup` |

**檢查、預覽（唯讀）**

| 要做的事 | 指令 |
|---|---|
| 一般更新檢查（備份＋比對＋健康檢查） | `npm run db:update` |
| 檢查備份檔存在、大小、能開啟、完整性、主要資料筆數 | `npm run db:verify-backup` |
| 檢查管理員登入的 .env 設定（NEXTAUTH_SECRET，不顯示值） | `npm run check:env` |
| 檢查程式資料夾有沒有誤放資料庫／設定檔、有沒有繞過固定資料夾的程式 | `npm run check:project` |
| 連到哪份資料庫、各區塊筆數、結構是否缺漏 | `npm run db:doctor` |
| 預覽生活區缺什麼（建議在 `--apply` 之前先跑） | `npm run db:restore-life` |

**內容來源**：公告、行事曆、IP 角色、網站設定、威洛助理在後台編輯，不需指令；生活區整批補內容用 `db:restore-life`；校園區整批補入工具待你提供內容後再做。

### D. 備份與還原
- 備份檔：`<固定資料夾>\backups\*.db`（`db:backup`、`db:update`、`db:push`、`db:restore-life --apply` 都會自動產生）。
- **上傳圖片不在資料庫裡**：請定期複製整個 `uploads\` 資料夾，或整個固定資料夾。
- 檢查備份：`npm run db:verify-backup`（唯讀）。備份不會被自動刪除，也不會覆蓋；上傳圖片的備份要另外複製 `uploads\`。
- 管理員在後台「刪除」圖片時，檔案只是移到 `uploads\_trash\`（不會真正刪除，可手動找回）。
- 還原步驟：①關閉網站 ②先把目前的 `dev.db` 另存一份（改名保留，不要刪）③把要還原的備份檔複製成 `dev.db` ④`npm run db:doctor` 確認 ⑤重啟網站。

### E. 只能在「確認備份後、手動」執行的特殊指令
以下**不會**出現在一般啟動或更新流程，而且必須明確加上 `-- --confirm` 才會執行（沒加會直接拒絕並說明）：
- `npm run db:seed`：會刪除不在內建清單的生活座標分類，並把配色與 IP 角色寫回內建版本。
- `npm run db:import-life`／`db:import-life-comics`／`db:import-life-vocabulary`：用內建資料覆蓋生活區名稱、單字、漫畫（含你在後台改過的）。
- `npm run db:reset-life-vocabulary`：刪除並重建生活區舊單字（`npm run db:audit-life` 只預覽，可直接執行）。
- `npm run db:migrate`：Prisma migration（目前專案沒有 migration 歷史，除非我明確說明，不要使用）。
`prisma migrate reset`、`db push --force-reset`、`--accept-data-loss` 在本專案的指令包裝裡一律拒絕。
**請不要直接執行 `npx prisma …`**（它會讀 `.env`，可能連到錯的資料庫），一律用上面的 `npm run` 指令。

## 六、Google Drive 如何設定（選填）

沒設定的時候，投稿照片會存在網站自己的資料夾，功能完全不受影響。要接 Google Drive：

1. Google Cloud Console 建立專案，開啟「Google Drive API」
2. 建立「服務帳戶（Service Account）」，下載金鑰
3. 在你的 Google Drive 建立資料夾，分享給服務帳戶的 email
4. 把三個值填進 `.env`，重新啟動網站

## 七、公告管理（常駐／節假日）

網址：`/admin/announcements`

公告分成兩種，**同時存在、互不覆蓋**：

- **📌 常駐公告**：不用設定日期，發布後會一直顯示在首頁輪播，例如「歡迎來到南部交換學生生活平台」這種長期性的內容。
- **🎉 節假日公告**：要設定開始／結束日期，只有落在這段期間內才會出現，例如「2026 中秋節放假通知」。

頁面上清楚分成兩區，各自有「新增常駐公告」「新增節假日公告」按鈕。每則公告可以編輯標題、內容（中英文）、排序、發布狀態，節假日公告還多了開始/結束日期跟「相關節日」備註欄位。首頁輪播會把目前有效的常駐公告跟節假日公告全部混在一起輪播顯示。

## 九、IP角色（身分卡）管理

網址：`/admin/characters`

每隻角色都是一張可以點擊翻面的「身分卡」，正面／背面都可以編輯：

- 角色名稱、角色圖片（正面大頭照；背景透明的 PNG 效果最好，會完整置中顯示、不會變形）
- 定位、個性、一句話（中英文）
- 設計理念標題、設計理念內容（中英文，顯示在卡片背面）
- 背面卡牌圖（依圖片原始比例顯示，不會被拉伸或裁切）
- **四個顏色**（卡片背景色／框線色／文字色／裝飾色）：每隻角色各自獨立
- 排序、是否顯示（IP 角色頁的身分證依「排序」由小到大排列，目前預設是布迪 → 帕菲 → 威洛；只會改順序，不會改角色資料編號）

### 首頁 IP 角色（對話框）——重要：怎麼連到首頁

首頁 Hero 有 3 個固定的角色位置，圖片是網站內建的（跟身分卡是不同的圖）。要讓「哪一筆 IP 資料」對應「首頁哪個位置」，在角色編輯頁用 **「首頁位置」下拉選單** 指定（首頁角色 1／2／3／不連結首頁）：

- 同一個位置同時只能給一隻角色，指定後原本佔用的角色會自動取消。
- 首頁點擊角色跳出的對話，一律是這個設定對應到的那筆資料的回覆——不是靠排序或名字猜的，所以改排序不會讓台詞跑到別隻角色。

### 首頁對話回覆（編輯頁最下方）

- 每隻角色可以新增**多句回覆**（中文＋英文），每句可以單獨啟用／停用、編輯、刪除。
- 首頁每次點擊該角色，會從它自己「啟用中」的回覆裡**隨機抽一句**；只有一句就固定顯示，沒有任何啟用的回覆就不會跳出對話框。
- 「首頁點擊這隻角色時顯示對話框」勾選取消，這隻角色就完全不跳對話框。
- 注意：要先儲存角色，才看得到「首頁對話回覆」區塊（新增中的角色還沒有編號可以掛回覆）。

## 十、中文學習管理

網址：`/admin/chinese-stages`

先選「生活」或「校園」，每個分區**固定規劃 8 關**（全新安裝時 `npm run db:seed` 會補齊 1～8 關，已有內容不會被動到）。進入某一關的「編輯內容」後，可以自由決定這一關有哪些學習頁、每頁是什麼類型、順序怎麼排（上移／下移）：

- **漫畫頁**（生活第 1～8 關的正式中英文漫畫已匯入；想換圖，在該關的漫畫頁直接替換即可。缺漏時用 `npm run db:restore-life` 補，不要用 `db:import-life`，它會把你換過的圖蓋回去）：「中文漫畫圖片」「英文漫畫圖片」各自獨立上傳（可多張）。兩種都有圖，而且勾選「允許前台翻轉中英文版本」時，前台漫畫上方會出現「點擊可切換中英文」，點擊漫畫以 3D 翻轉切換；只有一種語言的圖，或取消勾選，就不會顯示提示也不會翻轉。圖片都維持原始比例。前台預設先顯示跟網站目前語言一致的那一版（中文模式先看中文版、英文模式先看英文版），點擊漫畫切到另一個語言。
  - **生活 1～8 關漫畫已經預先匯入**（圖片在固定資料夾 `uploads\content\life-comics\`；缺的用 `npm run db:restore-life -- --apply` 補）。之後想換某一關，到 `/admin/chinese-stages/life` → 該關「編輯內容」→ 漫畫頁分別替換中文／英文圖片即可；這個匯入指令是獨立的，不包含在 `db:seed` 裡，所以重跑 seed 不會蓋掉你在後台換的圖。
- **生活 1～8 關的關卡名稱與單字已預先整理好**（資料在 `prisma/data/lifeVocabulary.ts`；缺漏時用 `npm run db:restore-life`）。舊的匯入指令只更新關卡名稱與單字頁，中文相同的單字會更新、不會重複；舊單字不在名單內的不會被刪除，會排到最後並列出來讓你判斷。之後想改單字，直接用後台，不需要再跑這個指令。
  - 如果生活區資料有殘留或重複（例如之前匯入失敗），先跑 `npm run db:audit-life`（只檢查、不改資料），再跑 `npm run db:reset-life-vocabulary`：會先把生活區備份到 `prisma/backups/`，再把生活 1～8 關的名稱與單字乾淨覆蓋（舊單字、重複的單字頁都清掉）；漫畫頁與題目頁不動；重複的生活關卡會取消發布。校園區完全不碰。
- **單字頁**（生活第 1～8 關的名稱與單字資料在 `prisma/data/lifeVocabulary.ts`，缺漏時用 `npm run db:restore-life` 補；同一關同一個中文單字會更新、不會重複，舊的其他單字不刪除）：中文／羅馬拼音／英文手動輸入，前台是橫向卡片網格（桌面 3～4 個一排）；語音由瀏覽器自動朗讀中文，不用上傳語音檔。
- **題目頁（填空／選擇／配對／是非）**：每種題型有專屬編輯介面，題目都有「中文題目」「英文題目」兩個獨立欄位。
  - 同一題型的所有題目會**集中顯示在同一頁**，使用者全部作答完按「提交答案」才一次判定；答錯的題目只提示「再試一次」，不顯示正確答案。
  - 一關裡有兩種以上題型時，前台題目頁上方會出現題型分頁籤（填空題／選擇題／配對題／是非題）可以切換。
  - 填空題：輸入完整中文句子＋指定要挖空的詞（也是答案），可再加其他可接受答案與提示。
  - 選擇題：選項數量不限，前台每次進入該頁隨機排列選項內容，但 A／B／C／D 標號固定。

## 十四、常見問題排除

**登入頁出現 `[next-auth][error][NO_SECRET]`／`/api/auth/error?error=Configuration`**：NextAuth 沒讀到 `NEXTAUTH_SECRET`。先執行 `npm run check:env`（唯讀，不會顯示任何密鑰的值），它會告訴你原因，常見的是：
- 專案根目錄沒有 `.env`（新版 ZIP 不含 `.env`，要從舊資料夾複製）或檔名其實是 `.env.txt`；
- `.env` 被存成 UTF-16（用 PowerShell 的 echo／Out-File 寫入會這樣）或第一行有 BOM，請用記事本／VS Code 另存為「UTF-8」；
- `.env.local` 等優先權更高的檔案把它設成空值；
- 終端機或 Windows 環境變數裡有一個同名的「空字串」變數，會蓋掉 `.env`（`Remove-Item Env:NEXTAUTH_SECRET` 後重開終端機）；
- 值後面混進了註解（例如範例裡的「← 絕對不能留空」），請只留下亂碼本身。
修好後必須**完全關閉並重新啟動** `npm run dev`（Ctrl+C 後再執行），Next.js 只在啟動時讀取 `.env`。要產生新的密鑰可執行：`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`，把結果貼進 `.env`（更換密鑰會讓目前已登入的人需要重新登入，不影響管理員帳號資料）。

**`@prisma/client did not initialize yet`**
```
npx prisma generate
npm run dev
```

**`Prisma Schema validation` 錯誤／後台功能打不開**
代表新版本改了資料庫結構，請照第一節第 5~7 步重新跑一次，不是只跑 `npm run dev`。

**一直無法登入 `/admin`**
檢查 `.env` 的 `NEXTAUTH_SECRET` 是不是空的。

**後台改了東西，公開頁面沒變化**
確認：有沒有按到「儲存」、該筆資料的發布/顯示開關是否打開、瀏覽器是否真的重新整理。都確認過還是沒變化，把截圖給我。

## 十六、威洛小助理設定（/admin/assistant）

左側選單「🤖 威洛小助理設定」。**這裡改的內容在按下「儲存設定」之前不會影響前台。** 目前小助理是「關鍵字判斷的假 AI」，沒有串接任何 AI 服務、不需要 API Key。

**第一次使用前**（只需一次）：更新資料庫新增兩張表（不會動到既有資料）。先 `npm run db:backup` 備份，再執行 `npx prisma db push`（只新增資料表／欄位；若出現要清除資料或 reset 的提示，請不要同意），再重新啟動網站。沒做這步之前，前台小助理仍會用預設值運作，但後台無法儲存。

- **基本設定**：啟用／停用、中英文名稱與歡迎訊息、預設語言、是否允許切換語言、是否顯示名稱／打字動畫、關閉後是否保留聊天紀錄（僅當次瀏覽期間）。停用後前台不顯示威洛，公開的回覆 API 也會拒絕請求。
- **外觀設定**：角色圖片（預設沿用首頁威洛，可另外上傳小助理專用圖；只影響小助理）、桌面／手機尺寸、初始位置（四個角落）與邊緣距離、對話框寬高與圓角、主色／輔色／背景／文字顏色（顏色選擇器）、發送按鈕樣式、陰影、是否可拖曳、是否顯示語言切換。
- **關鍵字與回覆**：新增／編輯／刪除規則，每條規則有關鍵字（逗號或換行分隔，中英文可混合）、中文回覆、英文回覆、啟用開關。**由上而下比對，第一個命中的規則回覆**，用 ↑↓ 調整優先順序。另可設定「沒有命中時」的中／英文預設回覆。下方有「快速測試」可直接試打一句話。

- **按鈕**：預覽變更（展開聊天視窗並捲到預覽）、儲存設定、取消變更（回到上次儲存的狀態）、恢復預設值（只載入預設值到編輯畫面，要再按「儲存設定」才生效）。

儲存後，前台重新整理即套用。使用者各自拖曳的位置存在自己的瀏覽器分頁中；管理員儲存新設定後，舊的拖曳位置會自動失效、回到設定的初始位置。

## 十七、網站有內容「不見了」？先跑資料庫診斷

很多區塊（中文學習、IP 對話、關於我們、校園時間、小助理…）的資料表是後來才新增的。**如果資料庫沒有同步更新，網站為了不當機會靜默顯示空白或內建範例，看起來就像內容消失了——但資料通常還在，只是讀不出來。**

在「平常執行 `npm run dev` 的專案資料夾」依序執行：

1. `npm run db:doctor`：唯讀診斷（不寫入、不刪除、不會建立新資料庫）。會顯示網站實際連到哪個資料庫檔案、缺少哪些資料表／欄位、各區塊實際有多少筆內容。
2. `npm run db:backup`：安全備份資料庫到固定資料夾的 `backups/`（網站執行中也可以）。另請自行複製固定資料夾的 `uploads\`（上傳的圖片不在資料庫裡）。
3. 如果診斷顯示缺少資料表／欄位：執行 `npm run db:push`（只新增、不刪除，會先自動備份）。**不要執行 `prisma migrate reset`，也不要同意任何「清除資料」的提示。**
4. 重啟網站。若某區塊數量是 0（例如生活單字、漫畫），那是「資料沒匯入」而不是被刪除，再用 `npm run db:restore-life`（先比對，確認後加 `-- --apply`）補入。

注意：現在資料庫與上傳圖片都放在固定資料夾（見二之一），新版程式解壓縮到新的資料夾不會再連到另一份空資料庫；若固定資料夾設定不對，網站與工具會直接報錯而不是默默用別份。

## 十八、生活區資料比對／恢復，與首頁公告順序

### 1. 生活區資料「只補缺」工具（不會覆蓋、不會刪除）

```bash
npm run db:restore-life            # 只比對：印出資料庫路徑、缺什麼、哪裡和內建名單不同（不寫入）
npm run db:restore-life -- --apply # 先自動備份到 prisma/backups/before-restore-life-時間.db，再只補缺的
```

- 關卡名稱：只在「不存在」或「空白」時補上；你在後台改過的名稱一律保留（只列出差異）。
- 漫畫：只在該頁的中文版／英文版圖片欄位空白時補上；圖檔在固定資料夾 `uploads\content\life-comics\`；缺少的內建圖會自動從程式的 `prisma\assets\uploads` 補上（不覆蓋）。
- 單字：以「同一關 + 中文」判斷，沒有才新增；已存在的不更新、不重排；不在名單內的單字完全保留。
- 題目、校園區、學習進度、答題紀錄：完全不碰。
- 資料庫結構落後（缺資料表／欄位）時會停止並提示先看 `npm run db:doctor`，不會硬寫。
- 注意：舊指令 `db:import-life*` 會更新已存在的名稱／單字／漫畫，`db:reset-life-vocabulary` 會刪資料，平常更新不要用。

### 2. 首頁重要公告的順序

1. 第一頁起：行事曆連動公告（今天是節日／紀念日 → 1～3 天內的節日 → 7、8 月演習提醒 → 1～3 天內的紀念日；同類依日期近的在前）。
2. 之後：後台「公告管理」的一般公告，維持原本順序。
3. 同一個行事曆事件只會產生一則；沒有符合條件的事件時，只顯示一般公告。
4. 在後台新增／修改／刪除行事曆事件後，重新整理首頁即會依新的資料重算（首頁為即時讀取，無快取）。

## 十九、行事曆「節日小圖」（節日詳情彈窗標題右側）

**自動依檔名套用（不用進後台）**
- 內建小圖放在專案的 `public/holiday-icons/`，**檔名＝節日名稱**，例如 `端午節.png` 會自動對應名稱含「端午節」的節日；多張都符合時取檔名最長的。
- **補假不放圖**（事件標為補假日，或名稱含「補假」）。
- 之後要加新圖：把「節日名稱.png」放進該資料夾，隨 ZIP 更新即可，重新啟動網站前台就會是新圖。目前內建：端午節、中秋節、國慶日、勞動節、921防災日。
- 後台若為某個節日另外設定了小圖，**後台的優先**。

**後台手動設定（選填）**：台灣行事曆管理 → 編輯 → 「節日小圖」，可上傳／更換／移除，按「儲存」才生效。圖片存固定資料夾 `uploads\content\`（UUID 檔名），更換或移除時舊檔移到 `uploads\_trash\`，不會永久刪除。這個後台欄位需要資料庫多一個可為空的欄位 `imageUrl`：
```
npm run db:update      ← 會先自動備份，並提示「有資料庫結構變更」
npm run db:push        ← 自動再備份，只新增一個欄位
```
沒有執行 `db:push` 時，網站、後台都照常運作，內建小圖也照常顯示；只是後台無法儲存小圖（會提示先執行 `db:push`）。

**前台顯示規則**：小圖在彈窗標題「節日名稱」右側，桌面約 100×100，手機自動縮小（64～80px），完整顯示不裁切不拉伸；沒有圖片就維持原本版面。

**生活第 1 關英文漫畫（自動更換）**：執行 `npm run db:update` 時（會先備份），若資料庫裡的英文漫畫還是舊的內建圖，就自動換成新圖 `life-1-en-v2.png`（新檔名存進固定 `uploads`，舊檔不動）；你在後台換過的不會被覆蓋。也可單獨執行 `npm run db:patch-content`。重跑不會重複。

## 二十、威洛動作圖片（思考中／生活資訊回答／暫時無法解決）

**狀態怎麼切換（由真正的請求與回應驅動，不是畫面假切換）**
| 狀態 | 什麼時候 | 優先順序 |
|---|---|---|
| 暫時無法解決 | 網站裡完全沒有相關資料、API 錯誤、逾時（15 秒）、停用、空回覆 | 1 |
| 生活資訊回答中 | 有找到資料，且問題屬於交通／飲食／購物日常／校園／文化節日類（依問題內容分類，不看字數） | 2 |
| 思考中 | 送出問題、等待搜尋結果（沒有刻意拖長的等待） | 3 |
| 待機 | 其他（包含「你好」這類有找到資料但不是生活資訊的一般回答（例如打招呼、中文學習）；動作維持約 4 秒後回待機） | 4 |

威洛現在是「資料搜尋」（見第二十一章），沒有串接任何 AI 服務、沒有 API 費用。**只有搜尋不到任何相關資料時才算「暫時無法解決」**；找到相關資料（即使只是同分類的延伸資料）就是有答案。

**後台上傳**：威洛小助理設定 → 外觀設定 → 「動作圖片」，三張可分別上傳／更換／移除，並顯示狀態名稱與「目前使用」的來源；可按「在右側預覽這個動作」；按「儲存設定」後套用前台。圖片存固定資料夾 `uploads\content\`，更換或移除時舊圖移到 `uploads\_trash\`，不會永久刪除。

**沒有上傳時**：「生活資訊回答」與「暫時無法解決」使用內建動作圖（`public/images/brand/willo-life-info.png`、`willo-unresolved.png`，前台更新後就是新圖，不用進後台）；「思考中」目前沒有內建圖，先用待機威洛。圖片壞掉或載入失敗時自動退回待機威洛，不會破圖。

**資料庫**：後台上傳需要 `AssistantSetting` 新增三個有預設值的欄位（`thinkingImageUrl`、`unresolvedImageUrl`、`lifeInfoImageUrl`），執行 `npm run db:update`、再 `npm run db:push`（自動備份、只新增欄位）。沒執行前，小助理與內建動作圖照常運作，其他設定也能儲存；只有後台上傳的動作圖片要等 push 後才能存（儲存時會提示）。


## 二十一、威洛的資料搜尋（取代「只靠關鍵字規則」）

威洛現在會**搜尋網站已發布的資料**，算相關程度、排序，列出最多 3～5 項候選，不需要為每筆內容設定關鍵字，也不使用任何外部 AI。

**搜尋哪些資料**：生活座標（分類與項目）、校園座標（校園文化、校內單位、各校午休／升旗時間）、台灣行事曆（節日介紹、由來、習俗）、中文學習（關卡、單字、題目）、你核准的「問題求助」知識，以及原本「關鍵字與回覆」裡的常見回覆（當成其中一種資料，不再是唯一觸發方式）。只讀「已發布」的內容；未發布內容、管理員帳號與設定都不會被讀取，搜尋與提問也不會修改任何資料。

**怎麼算分**：問題拆成詞（中文以兩字詞為主，英文去掉虛詞）→ 展開口語／同義詞（只增加分數，不會直接決定答案）→ 依欄位加權（標題 3、標籤 2.5、分類 1.5、內文 1、詳細內容 0.6），越稀有的詞分數越高 → 加上標題相似度。分數由高到低排序，同一筆資料只出現一次；分數太低的零星命中會被略過。結果太少時會擴大到同分類的資料。畫面上的「相關程度：高／中／低」只是資料與問題的相關程度，**不是 AI 的信心**。

**呈現方式**：高度相關→直接展示最相關的一項（再列幾項延伸）；多筆可能相關→列 3～5 項；沒有直接命中→顯示相關／同分類資料；完全沒有→說明網站暫時沒有直接答案，並引導到生活座標／校園座標／台灣行事曆／中文學習。每項有標題、摘要（取自資料原文）、分類、前往連結（沒有適合頁面就不顯示）；點「看詳細」，威洛會顯示該筆的詳細內容。回覆會註明「內容來自網站已收錄的資料；班次、票價、營業時間以官方為準」，不會編造店家、地址、票價或班次。

**限制**：沒有使用 SQLite FTS5：Prisma 不直接支援，且不能假設正式環境（或未來改用 PostgreSQL）一定有；目前資料量小，每次提問即時讀取資料並在程式內計分，結果永遠是最新的（沒有快取）。資料量成長到數千筆以上時再評估資料庫全文搜尋。同義詞表在程式裡（`lib/ai/search/synonyms.ts`），只用來輔助，新內容上架不需要維護它。

## 二十二、威洛「問題求助」（使用者提問 → 你整理成知識）

**使用者端**：威洛每則回答下方有「還沒找到想要的答案嗎？提交問題」，點了在原本的對話視窗裡展開表單（不跳頁、不清對話）：問題內容（必填）、分類（選填）、補充說明（選填），並可勾選附上「當次提問與威洛提供的候選標題」（不會附整段聊天紀錄）。伺服器確認存好才顯示「收到你的問題了！謝謝你幫助我們讓威洛變得更好。」失敗會保留內容讓使用者重試；重複點擊或重試不會重複建立；同一來源短時間最多送出數筆。不需要姓名、電話。

**後台**：左側選單「🙋 威洛問題求助」。
1. 「使用者投稿」可依處理狀態（待處理／整理中／已建立知識／暫不採用）、分類、提交日期篩選與排序；點一筆可看原始問題（不可改）、補充說明、提交時間、當時的提問與候選。
2. 整理：改狀態、寫「標準問題」、內部備註（只有管理員看得到）→「儲存整理內容」。
3. 建立知識：填標準問題、正式答案（中英文）、同義問法（選填）、分類、來源連結（站內路徑如 `/life/bus` 或 https 網址，選填）。可「儲存知識草稿」（不會被搜尋）、「核准並啟用」（威洛立刻搜尋得到）、「停用知識」／「重新啟用」。標為「暫不採用」會一併停用已啟用的知識。
4. 預覽：頁面中間會用和前台相同的搜尋方式，顯示威洛找到這筆知識時的卡片，也可以輸入別的問法測試找不找得到。
5. 「已建立的知識」分頁可查看所有知識（含草稿、已停用）並回頭修改。

**重點**：未核准的投稿**永遠不會**出現在威洛的搜尋結果；停用或修改後立即以最新內容為準。這不是即時客服，也不是威洛自動學習——是你核准知識後，由搜尋演算法找出來。

**資料庫**：新增兩張資料表 `AssistantQuestion`（投稿）、`AssistantKnowledge`（核准知識），不改任何既有資料表。執行 `npm run db:update`，再 `npm run db:push`（自動備份、只新增資料表）。沒有 push 之前：威洛搜尋照常運作（只是沒有「問題求助」知識），使用者提交會顯示「送出失敗」可重試，後台頁面會提示先執行 `db:push`。

## 二十三、每一關的「答題成功動畫」（中文學習）

**位置**：後台 →「📚 中文學習」→ 生活／校園 → 點進任一關 → 頁面上方「答題成功動畫」區塊。**每一關都有自己的區塊**，沒設定時會顯示「尚未設定動畫」。

**學生看到的流程**
1. 學生在**那一關**按「提交答案」，系統判定**全部答對**後，畫面中央跳出「答對了！」彈窗（半透明遮罩蓋住整個頁面，底下的題目、選項、提交按鈕在彈窗開著時點不到）。
2. 彈窗裡以較大的尺寸播放**那一關**的動畫（保持原始比例，不裁切、不變形；電腦與手機都不會超出畫面）。
3. **動畫播完會停在最後一幀，彈窗不會自動消失**，也不會自動重播。
4. 學生可以按「重新觀看」（從第一幀重播，播完再停在最後一幀）、「繼續學習」或右上角 ✕／Esc 關閉彈窗。重新觀看**只重播動畫**，不會重新判定答案、不會重複記錄。
5. 關掉彈窗後，頁面上還有「再看一次動畫」可以再開。
- 答錯不會跳彈窗。
- **沒設定動畫、檔案壞掉、瀏覽器不支援** → 仍然跳出同樣的彈窗，內容改成大勾勾圖示＋文字「回答正確！做得很好！」，沒有「重新觀看」按鈕。

**怎麼設定**
1. 進入某一關的編輯頁，在「答題成功動畫」按「選擇檔案」，選 MP4、GIF 或 SVG。
2. 選好就會立刻上傳並套用到前台（不用另外按儲存）；上方會顯示檔名、格式、大小與預覽，預覽也會播完停在最後一幀，可按「重新播放預覽」。
3. 想換，再上傳一次即可，舊檔會移到 `uploads\_trash`（可找回）。
4. 想拿掉：按「移除動畫」，這一關答對時就只顯示文字／圖示彈窗。

**各格式怎麼「停在最後一幀」，以及你要注意的限制**
- **MP4**：播完就停在最後一幀，不循環。請用 H.264，前台靜音自動播放。上限 8 MB。
- **GIF**：瀏覽器本身無法讓 GIF 停在最後一格，所以前台改成「自己逐格播放一次、畫完最後一格就停」，**即使 GIF 檔案本身設定無限循環也只會播一次**。上限 5 MB、單邊最多 4096 像素、最多 2000 格。檔案若無法解析會自動改顯示文字。
- **SVG**：靜態 SVG 直接顯示。動畫 SVG 因為瀏覽器沒有「動畫結束」事件，**只接受能判定結束時間、且會停在最後狀態的寫法**：
  - SMIL 動畫（`<animate>`、`<animateTransform>`、`<set>` 等）：每個都要有明確的 `dur`、有限的 `repeatCount`（不可 `indefinite`）、`begin` 只能是時間（例如 `0s`、`1.5s`，不可是點擊或其他動畫結束）、並設定 `fill="freeze"`。
  - CSS 動畫：不可 `infinite`，並要有 `animation-fill-mode: forwards`（或 `both`）。
  - 總長度不可超過 60 秒。
  - 無限循環、沒有 freeze、點擊才開始的動畫**上傳時會被拒絕並說明原因**；舊版已上傳、但不符合規則的 SVG，前台不會播放（只顯示文字），後台那一關會看到紅字提醒，請重新上傳。
  - 含腳本、外部連結的 SVG 一律拒絕；上限 512 KB。

**調整關卡順序或改名不會弄錯**：動畫是綁在關卡的內部編號（ID），不是「第幾關」或關卡名稱；每一關播的一定是自己的動畫，不會沿用前一關的畫面。

**檔案存哪裡**：`南得遇見你資料\uploads\chinese-animation\`；設定存在固定資料庫的 `ChineseStageAnimation` 資料表（以關卡 ID 為主鍵）。這次沒有新增資料表或欄位。

**第一次使用（與第二十四章共用）**：更新程式後在專案資料夾執行一次 `npm run db:update`，再執行 `npm run db:push`（自動備份、只新增資料表、不刪資料）。在這之前，中文學習照舊，只是後台無法儲存。

## 二十四、首頁主視覺裝飾（滿版透明底 PNG）

**位置**：後台 →「🎨 網站外觀」→「首頁主視覺裝飾」。

**範圍**：首頁導覽列下方的整個藍色主視覺（標題、介紹、搜尋框、兩顆按鈕、右側 IP 角色，以及它們之間與周圍的留白）。裝飾可以放在區域內**任何位置**，也可以超出邊緣（超出的部分會被裁掉，不會出現橫向捲軸）。

**固定層級**：主視覺底色 → 你上傳的 PNG → 標題／文字／搜尋／按鈕／IP 等內容。裝飾可以疊在文字或 IP 的**後面**，但永遠在它們下方，不會蓋住文字、不會擋住點擊（裝飾層不接收滑鼠與觸控），也不會改變原有版面。

**怎麼新增**：選一張透明背景的 PNG（只收 PNG；系統會真的檢查圖片裡有沒有透明像素），按「新增」，成功後立刻套用。可以新增很多張。

**每張可設定**：名稱、顯示／隱藏、X／Y 位置（圖片中心點，佔主視覺寬／高的 %）、大小（佔主視覺寬度 %）、旋轉角度、不透明度、前後順序（上移／下移）、更換圖片、刪除這張。**桌面版與手機版各自獨立設定**，改一邊不會影響另一邊。

**預覽與拖曳**：預覽就是真正的首頁（含實際標題、搜尋框、IP）。可以直接在預覽上**拖曳裝飾**改位置（只會改 X／Y，不會拖動首頁內容）。切換「桌面／手機」預覽，改的是對應那一組設定。調整完按「儲存全部變更」才會套用到前台。

**限制**：PNG 最大 2 MB、單邊最多 4096 像素、不支援「交錯式」PNG（匯出時取消交錯即可）。

**刪除**：按「刪除這張」會連同設定一起移除，其他裝飾不受影響；圖檔移到 `uploads\_trash`（可找回）。

**檔案與資料**：`南得遇見你資料\uploads\home-decor\`；設定存在 `HomeDecoration` 資料表。舊版（位置選左上／右上…）的設定會自動換算成新的 X／Y，不會遺失。

**第一次使用（與第二十三章共用）**：更新程式後執行一次 `npm run db:update`，再執行 `npm run db:push`（自動備份、只新增資料表、不刪資料）。在這之前首頁一切照舊，只是後台無法儲存。

## 二十五、刪除圖片與「必要圖片」規則

**全站統一**：所有圖片欄位都用同一個上傳元件。沒有圖片時顯示「上傳」；已有圖片時顯示「更換圖片」與「刪除圖片」（會先跳出確認）。刪除是**真的清空**，不是隱藏：儲存後前台恢復「沒有圖片」，重新整理、重新登入、重啟網站都一致。

| 台灣行事曆節日縮圖 | ✅ | ✅ | ✅ |
| IP 角色：身分證背面卡牌圖 | ✅ | ✅ | ✅ |
| IP 角色：**角色圖片／身分證正面照** | ✅ | ✅ | ❌ 必要 |

**實體檔案的安全處理**：刪除或更換後，系統會先檢查這個檔案是否還被其他欄位使用——**還有人在用就只解除目前欄位的關聯、不動檔案**；無法確定時也一律保留。確定沒人使用才移到 `uploads\_trash`（可找回，不會真的刪除）。

**注意**：外觀頁除了 Logo 之外的幾個圖片欄位目前沒有接到前台顯示（維持原狀，未改動）。

## 二十六、生活座標分類管理與英文內容保護

## 三十、圖片儲存：本機（local）或 Cloudinary

網站的圖片（後台上傳、首頁圖片、公告、生活／校園座標、中文學習、照片投稿、裝飾圖、答題成功動畫）全部經過同一個儲存層，可以在「本機固定資料夾」與「Cloudinary 雲端」之間切換。**資料庫不用改**：裡面存的永遠是 `/uploads/...` 網址。

### 如何切換
1. 在專案資料夾建立（或編輯）`.env.local`（不會進 Git／ZIP；不要把內容貼給任何人）：
   ```
   STORAGE_DRIVER=cloudinary
   CLOUDINARY_CLOUD_NAME=你的 cloud name
   CLOUDINARY_API_KEY=你的 API Key
   CLOUDINARY_API_SECRET=你的 API Secret
   ```
   （也可以改用單一變數 `CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME`。）
2. 關閉網站後重新 `npm run dev`。切回本機：把 `STORAGE_DRIVER=local`（或整行刪掉）再重啟。
3. 先用 `npm run check:cloudinary` 做連線自我檢查：只會在 Cloudinary 的 `nande-platform/selftest/` 建立並清掉它自己的 1x1 測試圖，不碰網站圖片與資料庫。

### 行為說明
- **舊的本機圖片完全不受影響**：Cloudinary 模式下，`/uploads/...` 先找固定資料夾，找得到就直接提供；找不到才向 Cloudinary 取圖。
- **不覆蓋**：同一個檔名不會被覆蓋（上傳前先檢查，並由 Cloudinary 端 `overwrite=false` 保證）。
- **CDN 快取注意**：Cloudinary 會暫時快取「檔案還不存在時」請求過的網址的 404。所以系統在上傳前不會去請求圖片網址（重複檢查改問 Cloudinary 管理 API），讀取遇到 404 時也會用管理 API 確認後改用帶版本號的網址。
- **新上傳的圖片**存到 Cloudinary 的 `<CLOUDINARY_FOLDER>/<資料夾>/<UUID>`（預設 `nande-platform`），資料庫記的仍是 `/uploads/...`。
- **「刪除」**預設是移到 Cloudinary 的 `nande-platform/_trash/`（可在 Cloudinary 後台找回），與本機的 `_trash` 一致；要永久刪除才設 `CLOUDINARY_DELETE_MODE=destroy`。
- 切回本機後，在 Cloudinary 模式期間上傳的圖片本機沒有檔案。要讓它們繼續顯示，可在 `.env.local` 加 `CLOUDINARY_FALLBACK=1`（本機找不到時改向 Cloudinary 取圖），或日後另外把圖片下載回固定資料夾。
- API Secret 只存在伺服器環境變數，不會送到瀏覽器；上傳由伺服器簽名。

### 目前不會自動做的事
- 不會把既有本機圖片搬到 Cloudinary（需要時另外規劃、先備份、可重複執行）。
- 圖片大小上限仍是 10MB（Cloudinary 免費方案單張圖片上限也是 10MB；影片 100MB）。若日後部署在 Vercel，平台本身限制請求約 4.5MB，需要另外調整。

## 三十一、把舊圖片遷移到 Cloudinary 前的唯讀掃描

遷移分三步，**每一步都要你確認後才做下一步**。目前只做到第一、二步，網站圖片、資料庫、Cloudinary 上的圖片都不會被動到。

1. 程式支援多層資料夾（例如 `/uploads/content/life-comics/…`），中文／空白／特殊符號檔名也能對應到 Cloudinary；同名但副檔名不同（`a.png` 與 `a.jpg`）會是不同的檔案。資料庫裡的網址完全不用改。
2. 執行唯讀掃描：`npm run audit:uploads`
   - 只讀取 `uploads` 資料夾與資料庫（只執行 SELECT），不上傳、不連網路、不修改、不刪除。
   - 報告存到固定資料資料夾的 `reports\uploads-audit-<時間>\`（`summary.md`、`files.csv`、`missing-refs.csv`、`files.json`），每次都是新資料夾，不覆蓋舊報告。
   - 可選參數：`-- --no-hash`（不計算 SHA-256、較快）、`-- --max-image-mb 10`、`-- --max-video-mb 100`、`-- --folder nande-platform`。
3. 把 `summary.md` 的內容貼給 Claude 確認後，才會做「第一批（目前網站使用中的圖片）」的上傳。歷史圖片與未被引用的圖片不會搬，但會完整保留在原處。

### 第一批正式遷移（使用中圖片）：`npm run migrate:uploads`

- 清單只來自掃描報告（`files.json`）中 batch=1 的紀錄，路徑、public_id、SHA-256 都用報告的值；上傳前會再確認本機檔案的大小與 SHA-256 仍和報告相同。
- 預設是**預演**，不連網路、不寫帳本：`npm run migrate:uploads`；加 `-- --check-remote` 會用唯讀方式問 Cloudinary 哪些已存在。
- 正式上傳要同時加三個參數：`npm run migrate:uploads -- --apply --confirm --expect-count <批次1的數量>`；可再加 `--limit 3` 先小量試跑。
- 已存在的 public_id 一律略過、不覆蓋；每一步寫入 `reports\uploads-migrate\ledger.jsonl`，中斷後重跑只會補傳沒完成的。
- 上傳後會下載回來比對 SHA-256 與大小。結果在 `reports\uploads-migrate\run-<時間>\`（result.csv、summary.md）。
- 不修改資料庫與圖片網址，不刪除或移動本機檔案，也不刪除 Cloudinary 上的任何檔案。

## 三十二、SQLite → Neon PostgreSQL 搬移前唯讀預檢：`npm run db:precheck-pg`

只做檢查，**不搬移、不修改任何資料**。第一次使用前請先 `npm install`（會安裝只在開發工具用到的 `sql.js`、`pg`）。

```
npm run db:precheck-pg -- --sqlite "C:\路徑\dev.db"
```

- Neon 連線字串只從 `.env.local` 的 `DIRECT_URL`（沒有則 `DATABASE_URL`）讀取，不顯示、不寫進報告；只檢查 SQLite 可加 `--no-neon`。
- SQLite 會先複製一份再讀，並比對原檔 SHA-256／大小／修改時間前後是否相同；Neon 只送出 SELECT／SHOW／WITH，且整個預檢在 `READ ONLY` 交易中。
- 報告在 `dev.db 所在資料夾\reports\pg-precheck-<時間>\`：`report.md`（完整報告）、`counts.csv`（各表筆數）、`findings.csv`（所有差異與異常）、`report.json`。
- 結束碼：0＝符合進入正式搬移階段；2＝報告已產生但不符合；1＝工具本身失敗。
- 報告不含連線字串、密碼，也不會顯示 passwordHash（管理員只顯示筆數與雜湊格式）。

### 單一上傳檔案的三方唯讀檢查：`npm run check:upload-one`

```
npm run check:upload-one -- --url /uploads/chinese-animation/<檔名>.mp4 --data-dir "C:\路徑\南得遇見你資料"
```

比對本機（大小、SHA-256）、搬移帳本（所有紀錄與狀態、哪些檔案沒有 verified）與 Cloudinary（唯讀查 public_id 與大小，並下載到暫存資料夾比對 SHA-256，用完即刪）。不上傳、不刪除、不移動、不修改任何檔案，不寫帳本。

## 三十三、SQLite → Neon PostgreSQL 正式資料搬移：`npm run db:migrate-to-pg`

把本機 SQLite 的 36 張表一次搬到 Neon。**預設只是乾跑（dry-run），不會寫入任何資料。**

### 步驟 1：乾跑（安全，隨時可跑）

```
npm run db:migrate-to-pg -- --sqlite "C:\Users\eno09\Desktop\南得遇見你資料\dev.db"
```

會列出每張表預計搬移的筆數與合計（目前預期 356）、Neon 各表目前筆數，以及能不能進入正式搬移。結果存在資料資料夾的 `reports\pg-migrate-dry-run-…\`（report.md、report.json、plan.csv，不含任何欄位內容或密碼）。加 `--no-neon` 可以不連 Neon，只看來源。

### 步驟 2：正式搬移（只在乾跑全部正常後，由你決定執行）

```
npm run db:migrate-to-pg -- --sqlite "C:\Users\eno09\Desktop\南得遇見你資料\dev.db" --apply --confirm --expect-total 356
```

缺少 `--apply`、`--confirm`、`--expect-total` 任何一個都不會寫入；`--expect-total` 必須等於來源實際總筆數。

### 它做了什麼、不做什麼

- 讀取 SQLite 的**複本**（原檔 SHA-256／大小／修改時間前後比對，絕不修改）；先用 Prisma 讀，再用另一種方式（sql.js）讀一次，逐表雜湊必須一致，否則停止。
- 只使用 `.env.local` 的 `DIRECT_URL`（直連）；主機名稱含 pooler 會拒絕。連線字串不會顯示或寫入報告。
- 36 張表只要有任何一張在 Neon 不是空的就拒絕；**工具從不 TRUNCATE／DELETE／重建資料**。
- 所有資料在**同一個交易**內寫入（先鎖表、再確認全空、依外鍵順序寫入）。寫完後在交易內驗證各表筆數、每張表內容 SHA-256、外鍵孤兒；任何錯誤或不符就整筆 ROLLBACK，Neon 回到 0 筆；全部通過才 COMMIT，COMMIT 後再用新的唯讀交易獨立驗證一次。
- 原樣保留 id、createdAt、updatedAt、空字串、NULL、JSON 字串；不重建管理員、不重新雜湊密碼。
- 缺少 Cloudinary 檔案（例如那支中文學習影片）不影響資料庫紀錄：不刪除、不略過。
- 不碰 Cloudinary、Google Drive、`.env.local` 與網站程式。

### 失敗了怎麼辦（安全重試）

失敗代表整筆已回滾、Neon 仍是空的，修正報告中說的原因後直接重跑同一行指令即可。若執行到最後連線中斷、不確定有沒有 COMMIT：先跑乾跑，若 Neon 各表已有資料，改跑

```
npm run db:migrate-to-pg -- --sqlite "C:\…\dev.db" --verify-only
```

它只讀取並比對 Neon 與來源（筆數、內容雜湊、外鍵），不寫入。**不要**自行清空 Neon 後重跑，先回報結果。

### Prisma 讀取用的暫存資料夾（EPERM 的處理）

讀 SQLite 複本時，工具會在**系統 TEMP** 建立獨立、唯一的暫存工作區（`nande-sqlite-reader-…`），在**獨立子程序**中產生並使用臨時 Prisma Client，子程序結束後才清除；不會在專案的 `node_modules` 建立任何資料夾，也不需要系統管理員身分。

- 暫存位置可用 `--tmp-dir "D:\可寫入的資料夾"`（或環境變數 `NANDE_TEMP_DIR`）更換；不可放在 `node_modules` 內。
- 清除失敗只會顯示警告與資料夾位置，不影響搬移結果與任何來源資料，可以安全手動刪除；下次執行會自動清掉本工具先前遺留（有標記檔、超過 1 小時）的工作區。
- 工作區內只有兩個指向專案 `prisma`、`@prisma/client` 的連結（不複製、不安裝套件）；清除時一律先移除連結並確認專案套件仍在，才會刪除其餘內容，絕不會動到專案的 `node_modules`。

測試：`npm run test:pgmigrate`（使用暫時的 PostgreSQL，不連任何真實資料庫）、`npm run test:pgreader`（暫存工作區、清除與安全防護）。

## 三十四、Vercel 部署與雙 schema（SQLite 本機＋PostgreSQL 正式）

- 本機照舊使用 SQLite，**不需要任何改變**；`npm run dev`、`npm run db:*` 維運工具都只用於本機 SQLite。
- 正式環境（Vercel + Neon）使用 `prisma/schema.postgres.prisma`，由 `scripts/prisma-generate.js` 自動選擇，不需要手動切換。
- **修改資料表或欄位時，`prisma/schema.prisma` 與 `prisma/schema.postgres.prisma` 兩份都要改**；`npm run check:project` 與 `npm run test:schema` 會提醒是否一致。
- Vercel 的環境變數、Preview 防護與部署前後檢查清單，請看 `docs/PostgreSQL與雲端儲存遷移指南.md` 第五章。
- `NANDE_DB_MODE=remote` 時，備份／診斷／匯入／seed／restore／reset／db push／migrate 等工具一律拒絕，避免誤動 Neon。
